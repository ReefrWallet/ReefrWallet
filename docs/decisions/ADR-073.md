# ADR-073: DeFi tab, plugin records and Uniswap V3 positions

* **Date:** 2026-11-21
* **Status:** Accepted
* **Context & Problem:** Accounts hold DeFi positions (LPs, perps, loans) that aren't token balances. Each protocol needs its own fetching and its own view, but the UI should only read the database, like balances do. Uniswap V3 positions are ERC-721 NFTs (ADR-072), so ownership comes from the NFT snapshot, which can lag the chain. Values must not mislabel principal as fees or keep counting history that a reorg removed.
* **Options Considered:**
  - One generic record per position with an opaque payload, written by per-protocol plugins (chosen).
  - A table per protocol: typed queries, but a migration and store code for every new plugin.
  - Fetching in the view: no store, but no total, no background updates and no offline view.
  - Uniswap subgraph or GeckoTerminal for fees/APR: one call, but new services, and pool APR isn't the position's.
* **Decision:**
  - **Records.** `DefiPositionModel`: account, plugin kind, plugin key, `Codable` payload, `usdValue` (sum of priced parts) and `isUSDValueComplete`. Cascade-deleted with the account.
  - **Plugins.** `protocol DefiPlugin` with `fetch`, `isCandidate` (config only), `isEligible` (from the committed NFT scan) and `requiredScanSource`. `fetch` returns one outcome per position: `.updated`, `.removed` (confirmed gone) or `.failed` (row kept). The store applies only named outcomes; plugins emit `.removed` themselves, so non-NFT plugins fit.
  - **Commit.** `commitDefiOutcomes` recomputes the account's NFT revision (snapshot source + scan time + owned keys/quantities + pending sends; metadata excluded) and writes nothing if it moved since the run read its input; the scheduler retries once.
  - **Scheduler.** `DefiScheduler`: every 5 min, on manual refresh, and on NFT saves that change the revision. One run per account and plugin; triggers during a run coalesce into one rerun. For candidates it calls `NFTService.enqueueRefresh` when the required scan is missing or stale, so the tab appears without opening NFTs. Override accounts check the node scan's own freshness, so a fallback to an indexer still retries the node.
  - **Eligibility.** Public path: chains whose Blockscout passed verification — Ethereum, Optimism (`explorer.optimism.io`), Unichain — with a completed indexer scan. Arbitrum, Base and Polygon Blockscout returned Cloudflare 403s to API clients on 2026-11-21 and are excluded; BSC, Avalanche and OP/Base on Etherscan need a paid tier. RPC-override path: any V3 deployment (incl. BSC, Avalanche) once its node scan is the snapshot.
  - **Uniswap V3 reads.** All `eth_call`s go through app-side Multicall3 `aggregate3` pinned to the latest block by hash (EIP-1898, falling back to its number). The head hash is rechecked before returning; a change voids the run. `ownerOf` is checked at that block: another owner, or the manager's `ERC721: owner query for nonexistent token` revert, removes the row; any other failure keeps it.
  - **History.** Mint from the NFT ledger (hash-checked) or a position-manager `Transfer(0x0 → , tokenId)` search from the manager's creation block or a lower token id's mint. `Collect`/`DecreaseLiquidity` sums and checkpoints are persisted only up to the safe block (`finalized`, else head − 64) with block hashes; every run rechecks them and rebuilds on a mismatch. The tail above is rescanned each run. Log queries share a budget of 20 per account per run, served round-robin from a rotating offset; exhaustion publishes the row with history `.loading`.
  - **History source.** Public RPCs serve `eth_getLogs` only for recent blocks (publicnode: "Archive requests require a personal token"), so log queries fall back to Etherscan's `getLogs` when a key is set, then the chain's Blockscout `/api?module=logs`. Indexer logs without a block hash take it from the node's header (not archive-gated). With an indexer the scanner starts with one wide range instead of 100k-block chunks.
  - **Totals.** Account, key store and sidebar totals add each position's priced `usdValue`.
  - **Fees and APR.** Fees column = pending fee growth, plus `tokensOwed` only when no liquidity was ever decreased; otherwise `tokensOwed` is shown as Claimable. Lifetime fees = collected + claimable − decreased. APR = lifetime fees (current prices) ÷ deployed USD ÷ age; blank without complete history, prices, deposits or a day of age. It includes previous owners' fees.
  - **Prices.** Stored `TokenModel.usdPrice` if under 15 min old and not failed, else a live `TokenPriceService` quote per run.
  - **UI.** DeFi tab (after NFTs) with a total (`≥` when partly unpriced), one section per kind; Uniswap V3 is a sortable table on Mac and Mail-style rows on iPhone.
* **Consequences:**
  - A new protocol is a plugin, a payload type and a view; no migration.
  - First history scans on long-lived positions take several runs on providers with small log ranges. Without an Etherscan key, history depends on Blockscout's anonymous rate limit.
  - Lifetime fees use current prices and include previous owners' fees; APR is an estimate.
  - Uniswap V3 positions on Arbitrum, Base, Polygon, BSC and Avalanche need an RPC override until a public NFT source works there.
  - Monad and Robinhood V3 deployments aren't included yet.
