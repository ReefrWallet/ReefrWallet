# ADR-024: Chain-specific fee estimation

* **Date:** 2026-10-06
* **Status:** Accepted
* **Context & Problem:** `BlockchainClientProtocol.estimateFee(for:)` with `FeeEstimateRequest`/`AnyFeeEstimateRequest`/`FeeEstimate` forced every chain into one EVM-shaped model: overloaded `data`, `gasPrice` meaning gwei, sat/vB or micro-lamports, and fields valid only per chain. Cardano and Tron stubbed it out. Callers already branched per chain to interpret the result.
* **Options Considered:**
  - Option A: Keep the generic API and document per-chain semantics: one entry point, but untyped and easy to misuse.
  - Option B: Drop it; each client exposes typed fee calls, and the app calls them per chain.
* **Decision:** Option B. Removed `FeeEstimate`, `FeeEstimateRequest`, `AnyFeeEstimateRequest`, `estimateFee(for:)` and `BlockchainClientFeature.feeEstimation`. Chain APIs:
  - Ethereum: `feeRates() -> EthereumFeeRates`, `estimateGas(from:to:value:data:)` (`to` optional for contract creation).
  - Sui: `referenceGasPrice()`, `gasCostSummary(transactionData:)` (`grossCost`, `netCost`).
  - Solana: `estimateFee(transaction:) -> SolanaFeeEstimate`, `recentPrioritizationFee()`.
  - Bitcoin: `feeRate()` (sat/vB), `fee(psbt:)`.
  `FeeEstimationService` resolves typed clients via `BlockchainClientProvider` (`ethereumClient`/`suiClient`/`solanaClient`/`bitcoinClient(for:)`).
* **Consequences:** Fee results are typed and unit-unambiguous. Fee estimation is no longer reachable through `any BlockchainClientProtocol`; a new chain needs its own branch in `FeeEstimationService`. Dapp contract deployments now get a real gas estimate instead of a 21 000 fallback.
