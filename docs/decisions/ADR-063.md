# ADR-063: Stagger idle transaction polling

* **Date:** 2026-11-09
* **Status:** Accepted
* **Context & Problem:** Accounts without transaction subscriptions polled every ten seconds. Each empty result saved an unchanged sync state, so wallets with many accounts continuously generated SwiftData writes and UI refreshes while idle.
* **Options Considered:**
  - Keep per-account timers and skip unchanged writes: removes database churn but still wakes every account together.
  - Use a shared polling coordinator: reduces bursts but adds a separate scheduler abstraction.
  - Reserve shared slots inside `TransactionSyncService`: keeps scheduling actor-isolated with little additional state.
* **Decision:** Poll non-subscription accounts once per minute after their immediate catch-up. Reserve poll slots two seconds apart across accounts. Do not save an empty page when the complete sync state is unchanged; persist any cursor, head, boundary, completion, or error transition.
* **Consequences:** Quiet wallets perform fewer network requests and avoid no-op SwiftData merges. Accounts can observe new transactions up to roughly one minute later, plus their stagger delay. Subscription-backed accounts remain immediate.
