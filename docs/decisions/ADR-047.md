# ADR-047: Periodic oldest-first token price updates

* **Date:** 2026-10-24
* **Status:** Accepted
* **Context & Problem:** Prices were fetched only by the sidebar's manual Update, after every account's balances, as a parallel burst per account. Until the user pressed it, no token had a price, and nothing kept prices fresh. Price sources (public JSON-RPC, CoinGecko Demo at 30 calls/min) are heavily rate-limited, so bursts fail and a failing token must not block the rest.
* **Options Considered:**
  - Timer-driven full sweep: simple, but every tick re-bursts every token and unpriceable tokens burn quota forever.
  - Persisted per-token freshness with a sequential, oldest-first queue (chosen): steady request rate, progress survives relaunches, and failures rotate to the back.
* **Decision:**
  - `TokenModel` gains `priceUpdatedAt` and `hasPriceFetchError` (lightweight migration). Every fetch outcome stamps `priceUpdatedAt`; success clears the flag and stores the quote, failure sets the flag and keeps the last good price.
  - `TokenPriceScheduler` (actor, started at launch) prices up to 100 due tokens per pass. Tokens reaching CoinGecko share requests (below). Due means: native token of a chain with an account, or a token with a non-zero balance, whose price is older than 5 min (10 min after a failed fetch), never-fetched first, then oldest first. Idle wait is 15 s.
  - A rate-limit error (HTTP 429, JSON-RPC 429/-32005) pauses the whole queue for 30 s, doubling to 10 min and resetting on the next success. Rate-limited tokens are not stamped, so they stay due; other failures are stamped so they can't hold up the queue.
  - Each `PriceSource` has a stable `id`. A successful fetch stores the quoting source's id in `TokenModel.priceSourceId`, and the next fetch tries that source first, then the rest in registry order. A failed fetch clears it. This saves the requests spent on sources that don't apply to the token (e.g. Chainlink's ENS lookups before CoinGecko), at the cost of not switching back to a preferred source while the stored one still works.
  - CoinGecko is batched: `/simple/price` takes up to 50 ids and `/simple/token_price/{platform}` up to 50 contract addresses per call, so a pass costs one call per platform instead of one per token. At a 5 min refresh that is ~8.6k calls/month for one request per pass, within the Demo plan's 10k.
  - The manual Update only ends the scheduler's idle wait; it never shortens a rate-limit backoff. `--disable-price-updates` (DEBUG) turns the scheduler off.
* **Consequences:** Prices appear shortly after launch and stay within about five minutes of the market for held tokens, without bursts against rate-limited sources. Unpriceable tokens cost one attempt per 10 minutes. Monthly CoinGecko usage scales with the number of platforms held, not tokens: above ~1 request per pass the 10k/month Demo quota is exceeded. On-chain sources (Chainlink, Uniswap, Cetus) are still one RPC call per token.
