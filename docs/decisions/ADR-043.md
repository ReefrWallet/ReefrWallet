# ADR-043: TronScan failures no longer fail Tron history pages

* **Date:** 2026-10-22
* **Status:** Accepted
* **Context & Problem:** A Trezor Tron account and its watch-only twin showed different history. Both stored the same `apilist.tronscanapi.com … TLS error`: `TronClient.transactionHistory` awaited TronGrid and TronScan together, so one TronScan failure threw the whole page. The Trezor account had been marked scanned past a transaction by an older version; the launch-time rewind (ADR-031) that repairs this never completed, so the row and its `method` stayed missing.
* **Options Considered:**
  - Fail the page (status quo): internal transfers stay exact, but any TronScan outage stops all Tron sync.
  - Skip internal transfers for the failed pass (chosen): sync keeps running; internal transfers in that range are missed until a later rewind or rescan covers them.
* **Decision:** `internalTransactionsPage` returns an empty, finished page on a non-cancellation error. Cancellation still propagates.
* **Consequences:** Tron sync and rewind no longer depend on TronScan. Internal TRX transfers received during a TronScan outage are not backfilled automatically.
