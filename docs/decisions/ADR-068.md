# ADR-068: Custom tokens and user-hidden tokens

* **Date:** 2026-11-14
* **Status:** Accepted
* **Context & Problem:** EVM and Tron balance refreshes read only stored tokens the account has held or transferred, so a token never seen in its history has no balance. Users also can't override which tokens go to Hidden Balances (`TokenModel.isHidden`: unidentified or unpriced).
* **Options Considered:**
  - Reuse `TokenModel.isIncludedInBalance`: already exists, but token upserts from sync overwrite it.
  - Add `TokenModel.isHiddenOverride: Bool?`: lightweight migration, written only by the user.
* **Decision:**
  - A Tokens tab (EVM, Tron) lists the chain's non-native tokens. Adding a contract address reads its info, stores the `Token` for the whole chain and queues this account's balance for it (`CustomTokenService`). An already stored token is only queued. Either way the token is set not hidden.
  - `isHiddenOverride` (`nil` = automatic) wins over the identity/price rule in `TokenModel.isHidden`, so it moves the token between visible and hidden balances and in or out of totals on every account. Set from the tab's Hidden column.
* **Consequences:** A zero balance isn't stored, so an added token the account doesn't hold shows only in the Tokens tab. An override is never reset to automatic.
