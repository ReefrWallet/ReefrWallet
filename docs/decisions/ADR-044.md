# ADR-044: Accounts are identified and ordered by `DerivationPath`, not `accountIndex`

* **Date:** 2026-10-23
* **Status:** Accepted
* **Context & Problem:** "Add Account" now accepts a custom derivation path (validated per chain by `DerivationPath(string:for:curve:scriptType:)`). `accountIndex` then no longer describes an account: a custom path has no meaningful index, yet the index drove numbering, sorting and Cardano/Bitcoin signing.
* **Options Considered:**
  - Keep `accountIndex` beside the path: two sources of truth that disagree for custom paths.
  - Drop it and use the path everywhere (chosen).
* **Decision:** `Account.derivationPath` is a `DerivationPath` (stored as its string). `accountIndex` is removed from `Account`/`AccountModel` (SwiftData drops the attribute). `DerivationPath` is `Comparable` (BIP-32 segment order, hardened after non-hardened) and sorts accounts per blockchain. The next default account is `max(default-path index) + 1` over existing paths, found by matching each path against the chain's default path. A custom path equal to a default one is named "#N"; any other is named after its path. Duplicate paths per key store and blockchain are rejected.
* **Consequences:** One source of truth; ordering and signing follow the path. Accounts without a path (watch-only) sort last by name and are named "#" plus the number of accounts on that blockchain plus one. WalletKit's Cardano and Bitcoin signer APIs (`CardanoAccountDescriptor`, `CardanoTrezorSigner`, `CardanoUnsignedTransaction.signed`, `BitcoinTrezorSigner`) take a `DerivationPath` and read the account index from it. `DerivationPath.validate(for:curve:scriptType:)` checks per-chain shape; `makeAccount` takes a path (default: the next one) and the sheet always passes one.
