# ADR-056: ENS names in the watch-only address field

* **Date:** 2026-11-07
* **Status:** Accepted
* **Context & Problem:** Watch-only EVM accounts needed a raw `0x` address. Users often know only an ENS name.
* **Options Considered:**
  - Resolve on submit via the ENS registry and resolver on Ethereum mainnet (chosen): no new dependency, reuses the lookup Chainlink feeds already did.
  - Resolve live while typing: more RPC calls and stale-result races for little gain.
  - Universal Resolver or a third-party API: adds a dependency or a trusted service; Universal Resolver would add wildcard and CCIP-Read support.
* **Decision:**
  - `ENSResolver` (extracted from `ChainlinkPriceSource`) calls `resolver(bytes32)` on the registry, then `addr(bytes32)` on the resolver, always on Ethereum mainnet whatever EVM network is selected.
  - `AddAccountView` accepts a valid address or a dotted name for EVM chains, resolves the name when the account is added and stores the resolved address. The ENS name becomes the account's name (lowercased) instead of "Ethereum #N"; the address stays the stored identity. A footer note explains the field takes either. Unresolved names show an alert.
  - Names are lowercased but not UTS-46 normalized; wildcard and CCIP-Read names are unsupported.
* **Consequences:** Adding a watch-only EVM account by name needs a mainnet RPC call; an offline or failing endpoint blocks it with an error. The account tracks the address at add time, not later ENS changes. Non-ASCII names fail to resolve until normalization is added.
