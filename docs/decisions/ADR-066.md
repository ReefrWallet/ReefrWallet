# ADR-066: SLIP-39 restore and the seed phrase field

* **Date:** 2026-11-11
* **Status:** Accepted. Supersedes [ADR-013](ADR-013.md)'s decision that BIP-39 entropy plus wordlist is every local key store's sole secret.
* **Context & Problem:** Restore accepted only BIP-39 phrases, in a tokenizer without word numbers or a word-count limit. Users with SLIP-39 backups (Trezor Shamir) had no way in. SLIP-39 master secrets are 16 or 32 bytes, not BIP-39 seeds, so the 64-byte seed contract, the Cardano Icarus derivation and the backup display all assumed BIP-39.
* **Options Considered:**
  - Port `sssmc39` or call a crate: none supports extendable backups. Chosen: a port of python-shamir-mnemonic in `walletkit-ffi`, checked against the official vectors.
  - Extend `WordTokenizerView` (ADR-015). Chosen: a new `SeedPhraseField`, which replaced `WordTokenizerView` entirely (read-only display uses `ReadOnlyPhraseView`); its editor keeps its position, so editing word 3 keeps it third.
  - Truncate a longer paste: can leave a checksum-valid prefix that restores another wallet. Chosen: reject the whole paste with a message.
  - Store shares: rejected; only the decrypted master secret is kept.
* **Decision:**
  - **Secret kind:** `KeyStore.SecretKind` (`bip39` default, `slip39`) via an optional `KeyStoreModel.rawSecretKind`; stores saved before it read as BIP-39. The sealed bytes are BIP-39 entropy or the SLIP-39 master secret (ADR-046 vault). The passphrase is not stored. A SLIP-39 store has no recovery phrase to show.
  - **Seeds:** `Seed(masterSecret:)` takes 16–64 even bytes; `Seed(rawBytes:)` stays 64-only. `KeyStore.localSeed` returns a `Seed`, so account creation and signing work for both kinds.
  - **Cardano:** SLIP-39 stores use the SLIP-23 root key. All four entry points (account key, native transactions, dapp transactions, CIP-8 `signData`) call one `account_private_key(CardanoRootSecretFfi, …)`.
  - **SLIP-39:** 20- and 33-word shares only; other lengths (e.g. 59-word BIP-39 conversions) are reported as unsupported. `Slip39ShareSet` checks identifier, extendable flag, iteration exponent, group threshold and count, word count, member threshold and unique member indices, and hands strict `combine` exactly the required groups and members. The set is combined on completion so a digest failure shows before the passphrase step.
  - **Passphrase:** an explicit step; printable ASCII 32–126, used exactly (no trimming or case change), anything else is an error, not stripped. PBKDF2 runs in-crate with a cancel check every 10 000 iterations on one serial executor, so a dismissed sheet stops within milliseconds and derivations never pile up.
  - **Save:** `KeyStoreService.saveLocalKey` seals, inserts and treats `ModelContext.save()` as the commit point: a failed or cancelled insert deletes only its model and discards the vault key; once saved, a failed re-fetch is not an error, so a retry can't duplicate.
  - **Generating:** Add Key Store offers one "New Mnemonic" option; the next step picks BIP-39 (12–24 words) or SLIP-39 (20 or 33 words), like Restore From Backup. SLIP-39 generates a random 128/256-bit master secret and its 1-of-1 share (empty passphrase, extendable, iteration exponent 1), shown once as read-only chips; the master secret is saved, the share is not. Multi-share generation is out of scope. The restore description now reads "BIP-39 recovery phrase or a SLIP-39 share" instead of listing word counts.
  - **UI:** `SeedPhraseField` shows numbered chips (green/red, × deletes the word) in 4 (Mac) or 3 (iOS) columns; the word being typed is plain text in the cell its chip will take, and a caret between chips takes no cell. Restore is step 1 type and word count, words, shares (SLIP-39), passphrase. Designs are in Penpot (Controls: word chip and field; Components: restore parameters).
* **Consequences:** SLIP-39 backups restore with Ethereum, Sui, Cardano and the other chains' keys derived from the master secret. Seed-only SLIP-39 stores can't be backed up from the app. A wrong passphrase opens a different wallet, as the spec intends. Strings added for the flow are not yet in the String Catalog. Extendable and non-extendable backups, passphrases, both secret lengths and Cardano SLIP-23 roots are covered by the official Trezor vectors and fixtures (`WalletKit/TestVectors/slip39.json`).
