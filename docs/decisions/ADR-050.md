# ADR-050: Penpot Controls page and Mail-style sidebar

* **Date:** 2026-11-03
* **Status:** Accepted
* **Context & Problem:** Penpot controls were spread across the Components page, some with only one platform, and composites (Fees, Parameters) were built from plain boards. The sidebar grouped key stores under kind headers ("Hardware Keys", "On This Computer"), which does not scale and differs from platform conventions.
* **Options Considered:**
  - Keep controls on Components and add missing variants: less churn, but no separation between primitives and composites.
  - Separate **Controls** page with Mac/iOS variants for every control, composites built from them: clear layering. Cons: the plugin cannot move main components between pages, so each control is recreated and instances swapped.
* **Decision:**
  - **Controls** page, grouped as Buttons, Inputs & Forms, Lists, Indicators, Menus, Bars. Every control has a `Platform` (Mac, iOS; Transaction Row also iPad) property. Includes new Text Field, Radio, Pop-up Button, Bar Button, Menu Item, Context Menu, Section Header, Account Row, Add Row and Mac Form Row variants. The old components were swapped out and deleted.
  - Composites (Fees, chain Transaction Parameters, account/settings/dApp parameter sets) use Form Section Header, Form Row and Form Footnote instances. Code blocks, recovery phrase grid and Mac key store kind radios stay plain boards.
  - The sidebar follows Apple Mail: each key store is a collapsible section (mailbox) and its accounts are rows (folders). Collapsed sections show the total value.
    - **Mac:** hovering a section header shows Add Account and the collapse chevron. Context menus (Key Store, Account) replace edit mode.
    - **iOS:** Edit enters edit mode, Contacts-style: red remove buttons on key stores and accounts, green add buttons on Add Account… rows, and an Add Key Store button. Edit Button control (Add/Remove) uses new System Green/System Red library colors.
  - iPhone account details follow the Mail message list: Large navigation bar (back, Send; account name and key store · value), **Account Tabs** filter chips (Balances, Transactions, Approvals, Staking, NFTs; the selected chip shows its label), two-line Balance rows (token · amount, price · USD value) and three-line Transaction rows with inset separators, and a bottom Toolbar (Filter Button, Search Field). An active filter turns the Filter Button into a "Filtered by" pill and search into an icon. The Filters sheet has an Addressed section (To account, To My Accounts, From My Accounts) and Include Unknown Tokens / Hide Zero Balances switches. New controls: Filter Chip, Filter Button, Search Field, Toolbar (Default/Filtered), Navigation Bar `Large` and `Sheet`, Bar Button `Prominent Icon`, Form Row `Check`/`Check Selected`.
  - Mac account details keep the table layout (header, Token Balances / Transactions / Approvals segmented control, Table Header and table rows per chain, Total Value summary) under the new sidebar. Mac Navigation Bar `Detail` is the title and Send only; Mac has no filter or search. New Mac controls: Table Header `Balances`/`Approvals`, Approval Row, Table Summary, Segmented Control `Approvals`; Mac Balance Row and Transaction Row are table rows.
  - New composites: **Sidebar** (Mac Default/Hover, iOS Default/Editing; iPad uses the iOS variant at 320pt) and **Account List**. The old Key Store Card/Row/Header and sidebar row components were removed.
* **Consequences:** Screens and composites depend only on Controls, so restyling a control propagates everywhere. iOS form composites are now 393pt wide with insets built into Form Row. The app's sidebar code (`SidebarView`, iPhone list) must be updated to match; the design is the target, not yet implemented.
