# ADR-060: Sui native staking

* **Date:** 2026-11-08
* **Status:** Accepted
* **Context & Problem:** Sui has send, balances and history but no staking. Staking SUI is one programmable transaction block (PTB) against the shared system state, and the result is an owned `StakedSui` receipt, not an account. The wallet must build, sign and follow it without ever losing track of a transaction whose outcome is unknown.
* **Options Considered:**
  - Dapp-style signing of a node-built transaction: no local control of bytes or gas; rejected.
  - Poll `ListOwnedObjects` only, no submission record: a crash after the broadcast loses the outcome; rejected.
  - Self-built PTB, persisted signed submission, proof-based recovery: more code, no unsafe state. Chosen.
* **Decision:**
  - **Actions:** `0x3::sui_system::request_add_stake` (stake), `request_withdraw_stake` (unstake, immediate, principal plus rewards through the last epoch, principal only while pending) and `0x3::staking_pool::split` then withdraw in one PTB (partial). Both parts of a split must hold the 1 SUI minimum, so partial needs a stake of 2 SUI or more.
  - **Builder:** WalletKit writes the PTB (shared system-state input, `NestedResult` arguments) and `TransactionExpiration::Epoch(current + 1)`. The digest is Blake2b-256 over the salted BCS bytes, computed in Rust over UniFFI so Swift has no second implementation. The decoder's dapp policy still rejects epoch expiry and shared inputs; only self-built transactions use the permissive path. BCS vectors come from the TypeScript SDK.
  - **Reads:** all pages of `ListOwnedObjects` filtered to `StakedSui`, keyed by pool id (inactive pools stay withdrawable, found through `inactive_validators`). Rewards are a separate read that may fail alone, ported from `staking_pool.move`: exchange rate at or before the epoch, zero fields mean 1:1, floored at zero, capped by the rewards pool, partial payout from the split principal. Missing data shows "unavailable", never zero. The summary says "Estimated rewards".
  - **No APY:** Sui has no source for it; the picker and stake sheet show validator commission.
  - **Funding:** gas must come from liquid coins chosen before execution. Budget is a multiple of the larger of computation and net (rebated) cost. MAX keeps a 0.02 SUI estimate for a later unstake; a manual amount may exceed it and the sheet says how much is left. Preparation simulates the exact bytes that are signed.
  - **Submission:** sign, then in one atomic database call persist the full submission (digest, bytes, signature, expiry epoch, input refs, chain id, start checkpoint), refusing if another is unresolved, then broadcast. The history placeholder is written only while the claim exists and removed with it when non-execution is proven.
  - **Resolution:** finalized effects (success or failure), else expiry with proof: the node's epoch is past the expiry and either every input is unchanged or a finalized transaction consumed an exact recorded input, else a gap-free checkpoint scan from the start checkpoint. Public nodes prune history, so "not found" alone proves nothing. A rebroadcast of a persisted submission never releases it; only a stateless rejection of the original send in the same process does, and the chain id is checked before every broadcast.
  - **Storage:** `StakingDetails.sui(SuiStakingDetails)`; pending submissions survive refreshes. Per-chain details moved to their own files.
  - **Signing:** local keys only. Trezor has no Sui firmware, so hardware and watch-only accounts see the position read-only. The network is gRPC; JSON-RPC is deprecated on public nodes.
* **Consequences:** Staking works for local-key accounts and a crash at any point resumes from a stored record. Staking is paused while a transaction is unresolved, with Check Again. An expired transaction on a pruning node may stay unresolved until history is reachable. Rewards are estimates. Out of scope: Mac staking sheets in Penpot, Trezor, liquid staking, APY.

## Implementation (2026-11-08)

* **WalletKit:** `Blake2b256`, `SuiProgrammableTransaction`, `SuiStakingTransactions`, `SuiStaking`, `SuiGRPCClient+Staking`/`+StakingRead`/`+Node`, `SuiStakingPreparation`, `SuiSubmission`.
* **App:** `SuiStakingPositionLoader` (behind `SuiStakingSource`), `SuiStakingService`, `SuiStakingModel`, view, sheet and validator picker on the shared `StakingSection` and `TransactionSheet`; `TransactionFeesView` gained a read-only Sui staking variant.
* **Verified:** WalletKit unit tests (vectors, reads, rewards maths, preparation, resolution matrix) and app tests (service, store, model); zero compiler and SwiftLint warnings in the app, app tests and WalletKit tests on macOS and iOS.
* **Not verified:** a live mainnet or testnet stake and unstake with a software key; the macOS UI-test target, which doesn't build here ("Cannot load module 'Testing'").
