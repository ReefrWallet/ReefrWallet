# ADR-016: Solana multi-address history scan and Cardano sync head

* **Date:** 2026-09-24
* **Status:** Accepted
* **Context & Problem:** Two chains under-reported to `TransactionSyncService`. (1) Solana history scanned `getSignaturesForAddress` for the wallet pubkey alone, but a transfer into an SPL token account that already exists names only that token account among the transaction's account keys — so every incoming SPL transfer after the one that created the account was invisible. (2) `CardanoClient.transactionHistory` returned no `head`, and `maintainForwardSync` sleeps in a loop until it sees one, so Cardano accounts never left backfill into forward sync.
* **Options Considered:**
  - Solana: derive each known mint's ATA and scan it. Needs the mint set up front — which is what history is supposed to discover.
  - Solana: scan the wallet plus every token account `getTokenAccountsByOwner` reports. Two extra RPC reads per page; discovers mints the wallet never signed for.
  - Cardano: report the tip from `blocks/latest` on every page. One extra request per page, including through a long backfill.
  - Cardano: report the newest block the page touched, and fall back to `blocks/latest` only when the page carries no height.
* **Decision:** Solana scans the wallet and all of its token accounts under both token programs, merging the per-address signature lists (deduped, newest-first). `before`/`until` only accept signatures drawn from the list they are passed with, so the persisted cursor changed shape: it is now a map of address → `{before, until, pendingUntil, drained}`, and `drained` keeps an exhausted address from being re-requested while the others page on. A page therefore carries up to `request.limit` signatures *per* scanned address. Cardano reports the newest block height in the page as `head`, reading `blocks/latest` only for a page with no height of its own; a failed tip read degrades to no head rather than failing the page.
* **Consequences:** Solana closed token accounts drop out of the scan — the node stops reporting them as owned — so history for a mint the wallet fully divested can't be backfilled past that point. Cursors persisted in the old single-address shape fail to decode and restart the scan from the tip; re-fetched pages upsert, so this is idempotent. Solana pages now cost two `getTokenAccountsByOwner` reads plus one `getSignaturesForAddress` per live address, and a wallet holding many token accounts fetches proportionally more transactions per page.
