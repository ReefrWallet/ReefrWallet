# ADR-031: Tron history heads, internal transfers, stable transaction ids

* **Date:** 2026-10-13
* **Status:** Accepted
* **Context & Problem:** Tron sync bugs seen on a live store:
  - TRC-20 rows showed "Pending": TronGrid's `transactions/trc20` has no block number.
  - Forward sync never started for accounts without native transactions: `head` was the max native `blockNumber`, so `currentHead` stayed nil once backfill completed.
  - TronGrid ignores `lowerBound`/`upperBound`, so every forward pass re-read the whole history.
  - TRX received as an internal transaction (e.g. a SunSwap/GasFree payout) never appeared: TronGrid's account history doesn't index internal transfers.
  - Every rescan after a relaunch added duplicate rows: `WalletTransaction.stableId` embedded `"\(PersistentIdentifier)"`, whose description includes a per-load object address (one Tron account had 2592 rows for 72 transactions).
* **Options Considered:**
  - Internal transfers: TronGrid `search_internal` (doesn't return them), TronScan `api/internal-transaction` (returns them; optional `TRON-PRO-API-KEY`), or tracing every block (too costly). TronScan.
  - Stable ids: the account's natural key (address + chain; collides across key stores) vs. the store URI from the encoded `PersistentIdentifier`. Store URI.
* **Decision:**
  - `TronClient.transactionHistory` scans `(minTimestamp, maxTimestamp]`: `head` is `upperBound` or the solidified tip (`walletsolidity/getblock`), bounds map to block timestamps (`min_timestamp`/`max_timestamp`, TronScan `start_timestamp`/`end_timestamp`). The range and per-stream positions live in the cursor; older cursors are discarded.
  - Rows without a height get one from `walletsolidity/gettransactioninfobyid`.
  - `TronNetwork.tronScanURL` (mainnet `apilist.tronscanapi.com`, Nile `nileapi.tronscan.org`) supplies confirmed, non-reverted TRX internal transfers to/from the account as `nativeTransfer` effects. Off for RPC overrides. Optional key: `TronScanAPIKey` default / `TRONSCAN_API_KEY`.
  - `TransactionSyncService` reruns a completed backfill once per session when it has no `currentHead`.
  - `stableId` uses `PersistentIdentifier.stableKey()` (store URI). `normalizeTransactionStableIds()` rewrites old ids and drops duplicates (keeping a row with a block height) at `startAll()`; a no-op afterwards.
* **Consequences:** Tron forward sync costs two indexer calls plus TronScan per pass instead of full-history paging; token-only pages cost one extra call per transaction. Internal transfers depend on TronScan's availability and rate limits. `LiveStoreTronSyncTests` reproduces against a copy of the local live store (skipped without one). `WalletTransactionSyncStateModel.accountStableId` still uses the description; it's only a unique tag, the state is found through the account relationship.
