# ADR-002: Subview Validation Signal for TransferView

* **Date:** 2026-09-15
* **Status:** Accepted
* **Context & Problem:** `TransferView` had grown to 555 lines (past the 500-line SwiftLint limit, requiring a `file_length` disable) by mixing the from/to/amount/token form, the per-chain fee form, debounced fee estimation, and transaction sending in one type. Validity was a single mutable `isNextButtonEnabled` flag poked from six separate `.onChange` handlers plus two near-duplicate refresh helpers, and the token `Picker` selected by `Balance` value with no `.tag()`, so picking a token never actually matched the selection.
* **Options Considered:**
  - Option A: Parent (`TransferView`) owns all text/selection state, each extracted subview reports only a `Bool`: less state duplication, but the parent's own `.onChange` on the moved-out fields would need to run before the child's validity update to avoid a stale read — an ordering hazard.
  - Option B: Each subview owns its own field state and reports an optional validated payload (`TransferParameters?` / `Fees?`), `nil` meaning "cannot proceed": more self-contained, avoids the ordering hazard since validity is derived from the same state that produced it, and each subview's fields are fully encapsulated.
* **Decision:** Use Option B. `TransferParametersView` owns the receiver/amount/token fields (plus the account-scoped `@Query` for balances) and exposes `@Binding var parameters: TransferParameters?`. `TransactionFeesView` owns the per-chain fee fields and exposes `@Binding var fees: Fees?`. `TransferView` keeps only orchestration (debounced fee estimation, signing, sending, progress/error UI) and derives `isNextButtonEnabled` as `parameters != nil && fees != nil` instead of storing it. The token picker now selects by `PersistentIdentifier` rather than by `Balance` value, since `Balance`'s synthesized `Hashable` includes `amount` and would silently drop the selection on a background balance refresh.
* **Consequences:** Each subview is independently testable and reusable, and the duplicated fetch-then-compare-snapshot logic in `TransferView` collapses into one helper keyed on `TransferParameters` equality. Fee fields now go blank while a new estimate is in flight (previously they kept showing stale values while `isNextButtonEnabled` alone went false), and `Estimate Fees` is now disabled until the address/amount validate. The token picker selection bug is fixed as a side effect of switching to identifier-based tagging.
