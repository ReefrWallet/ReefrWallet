# ADR-042: Unified send/sign view

* **Date:** 2026-10-21
* **Status:** Accepted
* **Context & Problem:** Sends (`TransferView`) and dapp requests (`DappRequestSheet` with per-chain `*PreviewView`s) are separate sheets with different layouts. Only Ethereum dapp transactions get editable fees. Bitcoin and Cardano have no dapp support.
* **Options Considered:**
  - Keep both sheets and restyle them: smallest change, but layout and fee handling stay duplicated.
  - One sheet built from per-chain parameter sections plus the chain's Fees section: one layout and one fee editor for every chain.
* **Decision:** One sheet, titled Send / Sign Transaction / Sign Message / Sign Typed Data, stacking: a per-chain parameters section → the chain's Fees section (transactions only) → buttons (Estimate Fees, Cancel, Next/Confirm). Designs are in Penpot: the Components page has one "\<Chain\> Transaction Parameters" variant set per chain, with properties Platform (Mac/iOS) and Usecase (Transfer, Transfer Native Asset, Sign Transaction, Sign Message, Sign Typed Data), plus a `Fees` variant set (Blockchain × Platform). Screens / Mac has a "Sheet / \<Kind\> / \<Chain\>" sheet for each:
  - Transfer (all 7 chains): From, Token + balance, Amount + MAX, Receiver. Cardano native assets add "Recipient ADA (lovelace)".
  - Transaction (Aptos, Ethereum, Solana, Sui, Tron): From, then the chain's decoded fields, then raw bytes/data. Gas and fee fields move from the previews to the Fees section.
  - Message (Aptos, Ethereum personal/typed data, Solana, Sui, Tron): From, then the message (EIP-712 also shows Domain).
  - Cardano Fees shows only a note, so its sheet has no Estimate Fees button.
  - Ethereum fees are edited in gwei; `Fees` keeps wei.
  - Code: `TransactionSheet` (layout), `Transaction/Parameters/*` (per chain), `TransactionFeesView` (per chain fees). Connect requests keep their own layout.
* **Amendments (implementation):**
  - Only Ethereum dapp transactions get editable fees. Aptos and Tron dapps receive only a signature for the bytes they built, and rewriting a Solana transaction voids its co-signers' signatures, so a fee edit would not match what the dapp broadcasts. These show the transaction's own fees read-only (`DappTransactionPreview.fees`), with no Estimate Fees button. `DappApprovalResult.approvedWithFees` stays Ethereum-only.
  - Not in Penpot, kept: the request origin under the title, the "fees set by the site" warning, EIP-712 Primary type and Types, and a Tron dapp transaction's estimated burn. Each is marked `// Not in Penpot` in code.
  - Dropped from the dapp sign sheet: Close Browser and the hardware confirm note (the hardware key prompt covers it).
* **Consequences:** The `*PreviewView`s are replaced by section views shared with `TransferView`. macOS parameter components are 440 pt wide, so long values are middle-truncated, and data/messages scroll inside a capped box. Every chain's fee estimate now carries `nativeFeeReserve`, so token sends show a USD cost; only native sends reserve it from MAX.
