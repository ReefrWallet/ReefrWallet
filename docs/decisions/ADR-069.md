# ADR-069: WalletKit as a prebuilt binary Swift package

* **Date:** 2026-11-19
* **Status:** Accepted
* **Context & Problem:** Using WalletKit required building its Rust core for 5 targets, plus protoc and a Homebrew libusb dylib that the macOS app linked from `/opt/homebrew`. ReefrWallet carried WalletKit as a submodule only so it could build it.
* **Options Considered:**
  - Keep the submodule and source build. No release work, but every developer and CI run needs Rust, and libusb isn't shippable.
  - Separate binary-only package repo. Clean history, but two repos to version.
  - `binaryTarget(url:checksum:)` in WalletKit's own `Package.swift`, with the ZIP on its GitHub release. One repo and one version.
* **Decision:**
  - WalletKit's `Package.swift` uses the local `Frameworks/WalletKitFFI.xcframework` when built, otherwise the release URL. `Sources/Generated` is committed, and CI fails if it is stale.
  - `Scripts/release.sh` is run by the **Release** workflow (`macos-26`) or by `make release`. It does the following:
    - Sets the version of all Rust crates (inherited from `[workspace.package]`), builds all slices, runs tests and docs, and packs the ZIP with `Licenses/`.
    - With `PUBLISH=1`, commits the version and checksum, tags, pushes `main` and the tag atomically, and publishes the release.
    - Tags are never reused; a broken release is fixed in the next patch version.
    - SwiftPM resolution of the release is verified by ReefrWallet's build and tests.
  - libusb comes from rusb's `vendored` feature: libusb1-sys's bundled 1.0.27, static, macOS slice only. The `CLibUSB` system library and the Homebrew link flags are gone, and `WalletKitRust` declares the frameworks it needs.
  - LGPL-2.1: the ZIP carries `libusb-COPYING` and `NOTICE`, each release attaches the libusb source, and the WalletKit README documents relinking via `[patch.crates-io]`. The app bundles the same license and notice in `Resources/Licenses/`.
  - ReefrWallet drops the submodule. `Tuist/Package.swift` uses `exact: "0.7.0"` unless `TUIST_WALLETKIT_PATH` names a local checkout.
  - WalletKit's Tuist `Project.swift` is removed. WalletKit is developed as a plain Swift package.
* **Consequences:**
  - Building the app needs no Rust, protoc or Homebrew.
  - Changing WalletKit for the app means a WalletKit release, then a version bump here, or developing with `TUIST_WALLETKIT_PATH`.
  - The release workflow pushes to `main` with `GITHUB_TOKEN`, so branch protection must allow it.
  - The LGPL plan needs review before the first publish.
