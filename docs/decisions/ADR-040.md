# ADR-040: Adaptive sidebar colors

* **Date:** 2026-10-21
* **Status:** Accepted (sidebar structure superseded by ADR-051)
* **Context & Problem:** Native secondary styling made sidebar headings and add buttons faint. The Xcode reference calls for a charcoal surface, near-white labels, neutral controls, and pale blue-gray network icons.
* **Options Considered:**
  - Replace the native sidebar background and selection: predictable colors, but loses native material and focus behavior.
  - Add semantic colors while retaining native selection.
* **Decision:** Add `SidebarBackground`, `SidebarLabel`, `SidebarSecondaryLabel`, `SidebarIcon`, and `SidebarControl` assets with light/dark and increased-contrast variants. Use the reference’s sRGB colors: background #252C35, labels #ECECED, headings/controls #BBBEC6, icons #CAEEFF in dark mode. Hide the macOS list scroll background and supply the adaptive sidebar surface. Account selection directly drives white text/icons because the row’s background-prominence environment did not reflect selection in the result screenshot. Key-store icons use the neutral control color. `StyledView` stores immutable inputs instead of initial `@State`, allowing selection-dependent colors to update. Mirror the assets in Penpot library colors, tokens, foundation swatches, and sidebar components/screens (ADR-037).
* **Consequences:** The macOS sidebar body has a stable reference-matched background; iOS retains its native surface. Toolbar controls, accent color, and selection remain system-owned. Penpot increased-contrast token sets are optional overlays on the corresponding appearance set.
