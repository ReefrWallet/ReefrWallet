# ADR-046: Protect local key store secrets with biometry or password

* **Date:** 2026-10-24
* **Status:** Accepted
* **Context & Problem:** Local key stores kept their BIP-39 entropy in the SwiftData database as plain bytes, readable by anything with file access, and signing needed no user authentication.
* **Options Considered:**
  - Store the entropy itself in the keychain behind an access control: needs a keychain item per read path, and the database no longer holds the secret's ciphertext for backup/migration.
  - Secure Enclave key: only P-256, so it can wrap but not hold the secret, and needs extra entitlements on macOS.
  - AES-GCM seal with a random 256-bit key per key store, the key kept in the keychain with `.userPresence`: one prompt per key use, works on iOS and macOS.
* **Decision:** `KeyVault` (`KeychainKeyVault`) seals entropy as `version | key id | AES-GCM(nonce, ciphertext, tag)` and stores it in `KeyStoreModel.mnemonicEntropy` (property name kept to avoid a schema migration; `KeyStore.sealedEntropy` in memory). The key lives in the data-protection keychain, `WhenPasscodeSetThisDeviceOnly` + `.userPresence` (biometry, falling back to device password). Opening the secret (`KeyStore.localEntropy/localMnemonic/localSeed`, now async) prompts with a reason: signing transactions and messages, adding accounts, showing the recovery phrase. No migration: databases with plaintext entropy must be recreated. Deleting a key store deletes its keychain key. Test and preview DI modes use `PassthroughKeyVault`.
* **Consequences:** Key stores from earlier versions fail to open. Every sign and every local account creation prompts the user. Keys are device-only, so a restored database/backup on another device can't unseal; recovery is by the phrase. Changing biometry enrollment doesn't invalidate keys (`.userPresence`, not `.biometryCurrentSet`). Running unsigned builds on macOS may fail keychain access without a team-signed keychain entitlement. Cardano and other chains share the same path. On iOS, Face ID needs `NSFaceIDUsageDescription` in the app's Info.plist (set in `Project.swift`); without it the keychain offers only the passcode. `open` evaluates `.deviceOwnerAuthentication` on an `LAContext` before the keychain read and passes that context to it: one prompt on devices, and a prompt at all on the simulator, which doesn't enforce `.userPresence`.
