# ADR-075: Revert Lend loans and custodian-held Uniswap V3 positions

* **Date:** 2026-11-23
* **Status:** Accepted. Extends [ADR-073](ADR-073.md).
* **Context & Problem:** Revert Lend's V3Vault takes custody of a Uniswap V3 position NFT used as loan collateral, so the account's NFT snapshot no longer lists it and the Uniswap V3 plugin can't see the position or its USDC debt.
* **Options Considered:**
  - Revert's undocumented `api.revert.finance` positions endpoint: lists vault-held positions but no debt, and may change without notice.
  - Vault `Add`/`Remove` logs: `owner` isn't indexed, so they can't be filtered by account.
  - One Revert row with the position and the loan: duplicates the Uniswap row and its code.
  - Vault views at a pinned block, collateral valued by the Uniswap V3 pipeline and saved as `uniswapV3` records.
* **Decision:**
  - **Scope.** Loans and USDC deposits in the vaults with Uniswap V3 collateral: Ethereum, Arbitrum, Base (`RevertLendDeployment`). Not the Aerodrome vault (Slipstream positions) or older test vaults.
  - **Reads.** One pinned block per run: `loanCount`, `lendInfo`, `vaultInfo`; `loanAtIndex`; `loanInfo` per loan and the IRM's `getRatesPerSecondX64(balance, debt)`, APR = rate × 31,536,000 ÷ 2^64. A failed loan list fails the run; a failed `loanInfo` keeps that loan's row.
  - **Collateral.** `UniswapV3Plugin.value` (shared with the Uniswap plugin: ownership, positions, pools, history, valuation) runs with `owner` = the vault and writes `uniswapV3` records keyed `chainId:tokenId` with `custodian` set. A position keeps one record whether the wallet or the vault holds it.
  - **Row ownership.** The Uniswap plugin never removes a stored record with a `custodian`; Revert removes its custodian records once a token isn't a loan. A position back in the wallet is revalued by the Uniswap plugin, which clears `custodian`.
  - **Records.** `revertLend` records: `loan:chainId:tokenId` (debt, position and collateral values, borrow APR, pair tokens) and `deposit` (amount with interest, supply APR).
  - **Totals.** The collateral counts at its value in Uniswap V3; a loan counts as −debt and the deposit as its amount, so totals are position − debt + deposit.
  - **UI.** Uniswap V3 rows held by a vault show "Revert Lend collateral". The Revert Lend section shows loans (pair, health = collateral value ÷ debt: healthy ≥ 1.2, at risk, liquidatable < 1; LTV, borrow APR) and the deposit.
* **Consequences:** Collateral history uses no ledger mint, so its mint is found by log search. Each run makes four vault rounds besides the Uniswap reads. Adding a vault is a `RevertLendDeployment` entry; other custodians can reuse `UniswapV3Plugin.value` and `custodian`.
