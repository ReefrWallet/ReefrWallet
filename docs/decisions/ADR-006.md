# ADR-006: Transaction token relationships and balance refresh

## Decision

Token-transfer effects link a transaction to the transferred token through a one-way SwiftData relationship. Historical synchronization discovers missing transfer tokens from RPC metadata, falling back to Etherscan transfer metadata, and persists them before saving the transaction page. Once either historical backfill or forward catch-up reaches its boundary, synchronization reconciles stored effects into the relation and invokes `BalancesService` to refresh the account's complete balance set.

## Consequences

Transactions retain a stable token reference even when the balance later reaches zero. A failed token metadata request fails the page so normal synchronization retry can complete the token relationship consistently; a post-sync balance refresh failure is logged and retried when the next pass completes.
