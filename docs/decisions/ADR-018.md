# ADR-018: Per-chain transaction row presentation

* **Date:** 2026-09-24
* **Status:** Superseded in part by ADR-034 (row dispatch and layout)
* **Context & Problem:** A single transaction table exposed raw effect kinds, omitted amounts, and had fields whose meaning differs by blockchain.
* **Options Considered:**
  - Option A: Keep one heterogeneous table: compact, but misrepresents chain-specific transaction data.
  - Option B: Duplicate a table per chain: supports custom columns, but duplicates selection and rendering logic.
* **Decision:** Use a precomputed presentation model, a chain presenter, and enum-backed row dispatch in a List. Rows share chrome but label block coordinates per chain and disclose all effects. Cardano enriches history with one net-lovelace effect from Blockfrost transaction UTxOs.
* **Consequences:** SwiftUI list identity remains stable and database relationships are resolved outside row bodies. Cardano history adds an address lookup per page and a UTxO lookup per transaction; failed enrichment degrades to a transaction without an amount. Native Cardano assets remain follow-up work.
