# ADR-011: TronGrid-backed Tron integration

* **Date:** 2026-09-21
* **Status:** Accepted
* **Context & Problem:** WalletKit had a Tron network marker but no usable address, client, transaction, or app integration. Reefr Wallet needs mainnet/Nile account data, transfers, history, configurable TronGrid access, and a truthful hardware-wallet boundary.
* **Decision:** Use TronGrid's HTTP API as the default provider (`api.trongrid.io`/`nile.trongrid.io`) with the optional `TRON-PRO-API-KEY` header. Generate standard Base58Check Tron addresses from secp256k1 public keys using BIP-44 coin type 195. Build native transfers and TRC-20 calls through the node-compatible wallet endpoints, sign `raw_data_hex` with a recoverable secp256k1 signature, and use the V1 native/TRC-20 feeds for history. `TRONGRID_API_KEY` is passed into test schemes by Tuist; the app can override it in Settings. Cache entries include that setting, so changes take effect on the next request. TRC-20 fee limits are exposed as a cost cap, not a priority fee. Trezor signing uses its `TronSignTx` protocol, passing TronGrid's structured `raw_data` fields and receiving the device's recoverable signature.
* **Consequences:** Software, watch-only, and Trezor-derived Tron accounts can receive, inspect history, estimate/build, sign, and broadcast native and TRC-20 transfers. Live Nile coverage requires a supplied `TRONGRID_API_KEY` and funded test account; no key is stored in source control.
