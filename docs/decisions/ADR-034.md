# ADR-034: Platform-adaptive transaction list with fee and method data

* **Date:** 2026-10-17
* **Status:** Accepted (table layouts superseded by ADR-051)
* **Context & Problem:** New designs (Figma "Transaction List Entries") define three layouts: an iPhone card row, a fixed-column iPad table, and a dense Mac table whose columns differ per chain. They show fee, method/action and named counterparties, which history didn't store. The per-chain row structs (ADR-018) differed only in a subtitle.
* **Options Considered:**
  - Option A: UI only, with "—" for missing fields: small change, but most new columns stay empty.
  - Option B: Add `fee`, `method`, `counterpartyName` to `BlockchainTransaction` and persist them: populated tables, but touches every history client and source.
* **Decision:** Option B. `BlockchainTransaction` gains optional `fee` (native smallest unit), `method` and `counterpartyName`; `WalletTransactionModel` stores them as optional columns (lightweight migration). Upserts keep a stored value when a poorer source re-syncs with `nil`. Sources: Blockscout/Etherscan (fee, method, names), EVM RPC (receipt fee, 4-byte selector table), Tron (contract type, `ret.fee`), Solana (`meta.fee`, parsed instruction, program names), Sui (gas summary, Move call), Aptos (gas, entry function), Bitcoin (inputs − outputs), Cardano (Blockfrost `txs/{hash}` fee). One `TransactionRow` replaces the per-chain row enum; presenters keep sign logic and add a block label and a `TransactionTableSchema` (column titles/visibility). macOS and regular-width iOS use `TransactionsTable`; compact width uses the row. Expandable details are dropped pending a detail screen. Row data the layout hides is exposed through invisible accessibility elements with stable identifiers for UI tests.
* **Consequences:** Existing rows show the new fields only after re-sync. Cardano adds one request per transaction. EVM method names from node-only history are limited to known selectors ("Contract Call" otherwise). Mac toolbar sub-tabs (Internal, Token Transfers, …) and the transaction detail screen are follow-up work.
