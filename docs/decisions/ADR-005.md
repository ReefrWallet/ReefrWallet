# ADR-005: Pluggable indexed EVM transaction history

- Status: Accepted
- Date: 2026-09-18

## Context

Standard Ethereum JSON-RPC nodes do not provide address-indexed historical transactions. Scanning blocks on public Sepolia nodes is rate-limited and cannot reliably recover old watch-only activity. Sui already provides filtered historical data through its native client.

## Decision

`TransactionSyncService` selects a `TransactionHistorySource` only for its descending historical backfill. `BlockscoutTransactionHistorySource` is the initial Moya-backed implementation for Ethereum and Arbitrum mainnets/testnets and persists Blockscout's opaque pagination cursor in the existing sync state. It accepts chain-ID endpoint overrides for BSC and custom EVM networks when a Blockscout-compatible endpoint is available.

Forward recovery and live transaction subscriptions continue to use the normal blockchain node. Ethereum and Arbitrum default nodes use Blockscout's public ETH-RPC endpoints; BSC retains PublicNode because Blockscout has no public BSC instance. Future Etherscan, Blockbook, or other indexed sources conform to the same protocol.

## Consequences

Historical EVM recovery is fast and avoids public-node block-scan limits. The backfill path now depends on Blockscout availability and response compatibility; normal node syncing remains available for live activity. This intentionally narrows the node-native-history rule in ADR-003 to EVM historical backfill.
