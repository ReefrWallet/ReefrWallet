# ADR-005: Pluggable indexed transaction history

- Status: Accepted
- Date: 2026-09-18

## Context

Standard Ethereum JSON-RPC nodes do not provide address-indexed historical transactions. Scanning blocks on public nodes is rate-limited and cannot reliably recover old activity. Sui already provides filtered historical data through its native client, but needs separate archive node for history.

## Decision

`TransactionSyncService` selects a `TransactionHistorySource` only for its descending historical backfill. `EtherscanTransactionHistorySource` is preferred over Blockscout for supported EVM chains when a user-supplied plaintext `UserDefaults` key is present, read live on each request. It merges Etherscan V2's `txlist` and `tokentx` feeds and pages each independently under the 10,000-result cap. `BlockscoutTransactionHistorySource` remains the fallback for Ethereum and Arbitrum mainnets/testnets and accepts chain-ID endpoint overrides for BSC and custom EVM networks when a Blockscout-compatible endpoint is available. `SuiArchiveTransactionHistorySource` uses Sui Foundation's archive gRPC services for Sui mainnet and testnet backfill. More will follow for other blockchains.

Forward recovery and live transaction subscriptions continue to use the normal blockchain node. 

## Consequences

Historical recovery is fast and avoids public-node block-scan limits. The backfill path now depends on archive provider availability; normal node syncing remains available for live activity. Synthesized Etherscan token-effect indexes can differ from RPC log indexes, so a transaction reached through both paths may contain duplicate effect rows. This intentionally narrows the node-native-history rule in ADR-003 to historical backfill.
