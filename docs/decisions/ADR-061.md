# ADR-061: Reduce wallet work during navigation and sync

* **Date:** 2026-11-08
* **Status:** Accepted
* **Context & Problem:** macOS Time Profiler captured hangs during sidebar redraws and on the Approvals tab. Forward sync and token linking faulted transaction history into memory to find token transfers.
* **Options Considered:**
  - Cache totals and token history across refreshes. Fast reads would require invalidation across every writer.
  - Keep live values and narrow the work performed on each update.
* **Decision:** Publish pointer movement to sidebar headers and update hover state only when it changes. Calculate sidebar totals on the database actor and coalesce refreshes after relevant saves. Show the token name in Approvals and remove its balance query. Prefetch tokens for approval and balance snapshots. Query stored token-transfer effects directly, link only missing balances, and load history hints only for EVM node scans.
* **Consequences:** Sidebar totals still follow stored prices and balances. Historical transfer assets remain scoped to their account. Existing stores need no schema migration.

## Verification

In 45-second Debug recordings, moving totals off the main thread removed 26 seconds of sampled sidebar valuation work. The longest recorded stall fell from 2.07 seconds to 364 milliseconds. Shorter stalls remain during SwiftData account queries.

## Follow-up

A repeat trace during account and tab switches found duplicate account queries, main-thread transaction row preparation, and continuous history writes. The sidebar shares the root account query. The macOS Transactions and Approvals tabs mount their contents when selected. Balance and approval snapshots refresh on the database actor after relevant saves, and transaction row preparation runs there too. Backfill writes reserve slots one second apart across accounts after the first page, while live sync continues independently. Page writes reuse the encoded account key and initialize new rows once.

Transactions and approvals read 40 rows at a time. Each tab prefetches one page and requests another near the end of the loaded rows. Search, transaction filters, and approval Select All can read the remaining pages. Relevant saves refresh the loaded window in the same order. Snapshot reads create their SwiftData context off the main thread. Exact-value accessibility markers used by UI tests are limited to test mode.

Token balances share the same paging state. A lightweight balance index, scanned in batches, keeps totals and sorting accurate before full rows are loaded. Hidden tokens have a separate page sequence that starts when the disclosure opens. Token images share a bounded decoded cache and HTTP disk cache, with one download per URL at a time.

Account deletion uses a scoped SwiftData batch delete so the store can cascade history removal without loading the account's relationship graph. Sync cancels both tracks and checks cancellation before persisting a page. A macOS test wallet with 171,000 transactions verified that deleting the account removed its transactions and effects and preserved the other account's history.

The shared write context is created off the main thread so the progress HUD can render during a large delete. The HUD appears when the stored transaction count exceeds 1,000. Transaction pages continue until the store has no more rows, replacing the former 500-row display limit.
