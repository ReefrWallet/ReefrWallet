# ADR-028: Trezor Solana message signing uses OCMS v1

* **Date:** 2026-10-09
* **Status:** Accepted
* **Context & Problem:** `SolanaTrezorSigner.sign(message:)` sent `SolanaSignMessage` with raw bytes in field 2 (OCMS v0, `trezor-client 0.1.6` on crates.io). Current firmware reserves field 2 and requires `SolanaOffchainMessageV1 { string message; repeated bytes signers }` in field 4, so a real device answered "Failed to decode message".
* **Options Considered:**
  - Wait for a crates.io `trezor-client` release with v1: no code change, but Solana message signing stays broken on up-to-date devices.
  - Pin `trezor-client` to a trezor-firmware git revision with v1 (chosen): works now; the revision must be bumped deliberately.
  - Hand-roll the protobuf message outside `trezor-client`: avoids the git pin but duplicates its wire handling.
* **Decision:** `walletkit-trezor` depends on trezor-firmware's own `rust/trezor-client` at rev `6ab39e95`. That version dropped the legacy (<2.3.0) `PassphraseRequest._on_device` flag, so both branches reading it were removed; the host always supplies the passphrase, as modern firmware already required. `solana_sign_message` now takes `(message: String, signers: [Data])`; `SolanaTrezorSigner` sends the account's key as the sole signer. The device signs its own serialization (`\xffsolana offchain` ‖ version ‖ signer count ‖ signers ‖ message), exposed as `SolanaTrezorSigner.offchainMessageBytes(_:signer:)` for verification.
* **Consequences:** Message signing works on current firmware (verified on a real device). A Trezor signature covers the OCMS-wrapped bytes, not the raw message, so a dapp verifying it over its original bytes fails; the software signer still signs raw bytes. Only non-empty UTF-8 messages are supported on Trezor (`unsupportedFeature` otherwise). `trezor-client` is now a git dependency until a release carries v1.
