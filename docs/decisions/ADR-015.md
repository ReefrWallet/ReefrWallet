# ADR-015: Word-tokenizing seed phrase entry

* **Date:** 2026-09-22
* **Status:** Superseded by ADR-066 (`WordTokenizerView` removed)
* **Context & Problem:** Seed phrase entry/display used two identical `TextEditor`s validated only as a whole phrase via `Mnemonic.fromPhrase`, so a single mistyped word in a 24-word backup gave no indication of which word was wrong, and nothing restricted typing to characters that can occur in a BIP39 word.
* **Decision:** Export `wordlist_words` from `walletkit-ffi` (the `bip39` crate's own `Language::word_list()`) rather than bundling wordlist resources in the app, which would duplicate data WalletKit already owns and could drift from it. Build `WordTokenizerView` around a single ordered array of entries (`.word`/`.editor`), where the in-progress editor stands in for the caret, instead of an overlay on one `TextEditor` or a macOS-only `NSTokenField` — the array model works identically across the app's `.mac, .iPhone, .iPad` targets and makes "insert between two words" and "words shift on delete" fall out of plain array mutation. Coloring is derived on render from wordlist membership, never stored, so it can't drift from the committed text.
* **Consequences:** Seed phrase entry/display now shows per-word validity and blocks disallowed characters at the keystroke, for both restore and freshly-generated (read-only) phrases. Precise cursor-position interactions (e.g. arrow keys mid-word) are approximated as "editor is empty" rather than true caret offset, since SwiftUI's `TextField` doesn't expose one; revisit if that proves confusing in practice.
