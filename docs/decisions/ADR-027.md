# ADR-027: App-owned pluggable token-price sources

* **Date:** 2026-10-08
* **Status:** Accepted
* **Context & Problem:** Token pricing had leaked Chainlink, Uniswap, Cetus, and ENS-specific policy into WalletKit's generic blockchain client protocol. New off-chain and chain-specific price providers would require further WalletKit API expansion despite being app market-data policy.
* **Options Considered:**
  - Option A: Keep `getTokenPrice` on `BlockchainClientProtocol`: one call site, but every client owns irrelevant provider policy and new sources widen WalletKit.
  - Option B: Move pricing into a Reefr Wallet source registry: chain transport stays in WalletKit and the app can add on-chain or off-chain sources independently.
* **Decision:** Use Option B. `TokenPriceService` owns ordered `PriceSource` implementations and persistence. Initial sources are Chainlink, Uniswap V3, and Cetus; they return `nil` when not applicable so later sources may try. ENS resolution/namehash, Chainlink decoding, Uniswap pool/TWAP logic, Cetus decoding, and their constants belong to the app. WalletKit retains only generic RPC, ABI, object, token-metadata, and address primitives.
* **Consequences:** Adding a CEX or other provider is app-only work and consumers depend on one service. WalletKit loses its generic price API and its price-specific tests. Source order is now an explicit app policy, and a failed preferred source may fall through to a later compatible source.
