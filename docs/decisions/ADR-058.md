# ADR-058: Cardano receive addresses

* **Date:** 2026-11-07
* **Status:** Accepted
* **Context & Problem:** Cardano accounts show only `0/0`, though the account key derives any address (ADR-013). People need to see and hand out more receive addresses, with amounts. Signing, discovery and dapp calls search only a bounded index range, so an address handed out beyond it would be unspendable or unrecognized.
* **Options Considered:**
  - Derive and query on every tab open: no schema, but slow offline and no amounts without a network read.
  - Store rows and amounts, refreshed with balances (chosen).
  - Store only added indices and read usage live: amounts still need a read per view.
* **Decision:**
  - `ReceiveAddressModel` (address, index, `isUsed`, lovelace; `nil` = unchecked), cascade-deleted with its account, plus `AccountModel.receiveAddressesObservedAt` (`nil` until discovery first succeeds). Lightweight migration; existing accounts fill in on the first refresh.
  - Adds are offline and insert-only. Refresh updates rows in place and never deletes, so an added address stays listed.
  - One `/utxos` read (`CardanoClient.utxoSnapshot`) feeds account balances and rows. A refresh of one account runs one at a time (task chain in `BalancesService`), so an older read can't overwrite a newer one. Balance totals absent from the snapshot are zeroed; an `/addresses` failure still saves balances.
  - A UTxO is evidence of use alongside `/addresses`, which can lag. `addressUsage` and the signer resolver use it, so a freshly funded `0/500` is found, listed and signable.
  - `CardanoAccountDescriptor.addressIndexLimit` (1,000) bounds discovery, transfer signing, the sheet and `getUnusedAddresses`. `nextExternalIndex` returns newest + 1, else the lowest free index, else none. The sheet warns past 20 addresses beyond the last on-chain used one, since other wallets may not restore it.
  - `signData` proves a locally issued address by deriving it from the account key before any network call.
  - First and later pages differ on 404: first page means empty; later means failure, so a partial read can't zero amounts.
* **Consequences:**
  - Amounts and used flags are as fresh as the last refresh; offline they stay as stored. Rows show "—" until checked.
  - Row amounts cover ADA at external addresses only. They can differ from the account total if another party's payment key shares the stake key.
  - `addressUsage` still throws on a listed address the account doesn't own (existing CIP-30 behavior); the tab and refresh ignore it.
  - Funds above index 999 sent from another wallet stay counted but unspendable here.
  - Staking tab, change addresses (role 1) and per-address native assets remain out of scope.
